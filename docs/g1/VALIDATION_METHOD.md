# G1 정책 검증 방법

설치 성공, 코드 실행, 동작 데이터의 기구학 오차, 학습된 정책의 실제 동역학 성능을 각각 구분한다. Quest의 실제 연결은 별도의 장비 검증이며, 가상 입력 수신 또는 시뮬레이터 실행만으로 확인됐다고 표시하지 않는다.

## 독립 기준선

`--zero-policy`는 신경망 대신 29개 액션에 0을 넣어 **중립 관절 PD 목표**를 유지한다. 모션 목표와 환경의 참조 자세 초기화는 그대로 사용한다. 따라서 이것은 ‘아무 제어도 없는 로봇’이나 ‘목표 동작을 그대로 재생하는 로봇’이 아니라 **중립 PD 제어 기준선**이다.

```bash
bash scripts/g1/run.sh evaluate --headless --zero-policy \
  --num-envs 64 --seed 42 --steps 1500 \
  --motion-file data/motions/g1_stand_v1.npz --record-trace \
  --output runs/baseline_stand_v3

bash scripts/g1/run.sh evaluate --headless --zero-policy \
  --num-envs 64 --seed 2026 --steps 3000 \
  --motion-file data/motions/g1_mixed_v1.npz --record-trace \
  --output runs/baseline_mixed_v3
```

학습한 정책과 비교할 때는 같은 데이터, 평가 클립 분할, seed, 로봇·관측·액션 계약과 시뮬레이션 길이를 사용한다. 실행 시간이 다르다고 훈련 성능이 다른 것은 아니다. GPU에서 학습과 평가를 동시에 실행하면 wall-clock 속도가 바뀌므로 시뮬레이션 초 단위로 비교한다.

## 두 종류의 측정

`result.json`의 `mean_metrics`는 모든 환경에서 얻은 **자동 리셋 직전** 측정의 집계다. 실패 직전 상태까지 포함하며, 64개 환경 전체에 관한 증거다.

평가 모드에서는 `failure_events.json`에도 모든 환경의 낙상 직전 상태를 저장한다. 환경 번호, 스텝, 동작 클립과 반사 재생 위상, 골반 높이·기울기, 상태 유한성과 관절 목표 제한 정보를 포함한다. 최대 10,000건을 보관하며 초과 건수는 숨기지 않고 별도 기록한다. 이 기능을 추가하기 전 평가에는 해당 파일이 없다. 시간 제한과 낙상이 같은 스텝에 발생하면 낙상으로 한 번 센다.

`trace.npz`는 **환경 0 하나의** 목표점, 실제 점, 관절, 액션, 명령과 종료 표시를 기록한다. 기록 위치가 `env.step()` 뒤이므로 `done=True`인 행에는 이미 자동 리셋된 자세가 들어갈 수 있다. 다음과 같이 처리한다.

- 기본적으로 종료 행과 앞뒤 1행을 추적 오차·속도 분석에서 제외한다. `--reset-guard`로 범위를 명시할 수 있다.
- 관절 속도와 액션 변화는 유효한 연속 행의 차분만 사용한다. 서로 다른 에피소드 사이를 연결하지 않는다.
- 제외 행 수와 원래 리셋 수를 모두 보고한다. 낙상 수, 완료 에피소드 수, 전체 환경 집계에서 실패를 삭제하지 않는다.
- 이 trace는 환경 0의 사례다. 환경 전체의 평균 또는 전체 관절·액션 유한성 검증으로 확대 해석하지 않는다.
- trace의 목표점은 관측 갱신 이후 값이다. 보상 계산에 사용한 직전 목표와 제어 1스텝 정도 차이가 있을 수 있으므로 population 지표와 trace 지표를 동일한 수치라고 기대하지 않는다.

유한하지 않은 관절·액션·목표점·실제 점이 있으면 해당 행 수를 보고하고 `finite=False`로 표시한다. 숫자가 아닌 값을 제거한 뒤 성공으로 표시하지 않는다.

## 측정값의 해석

- `hand_error_m`, `head_error_m`: 해당 목표점까지의 유클리드 거리. 단위는 m.
- `fall_rate_completed_episodes`: 완료 에피소드 중 낙상으로 끝난 비율. 아직 완료된 에피소드가 없으면 `null`이며, 낙상률 0이 아니다.
- `falls_per_simulated_minute`: 전체 병렬 환경의 시뮬레이션 시간 합으로 정규화한 낙상 빈도.
- `mean_completed_episode_seconds`: 완료 에피소드만의 길이 평균. 진행 중인 에피소드는 별도 요약한다. 성공적으로 오래 유지되는 에피소드가 측정 종료 시 미완료일 수 있으므로 이 평균만으로 평가하지 않는다.
- `joint_speed_rad_s`, `action_step_change`: 리셋 경계를 제외한 환경 0의 값. 액션 기록은 wrapper가 자르기 전 신경망 출력일 수 있다.
- `response`: 축별 목표·실제 움직임의 표준편차, 범위, 상관관계, 단순 회귀 이득, 최대 0.5초 양의 지연 탐색. 목표 변화가 5mm 표준편차 이하이거나 실제 변화가 1mm 이하이면 상관관계와 지연을 산출하지 않는다. 서로 다른 에피소드 간의 지연 상관도 계산하지 않는다.

낙상이 잦으면 매번 성공적인 초기 자세로 돌아가기 때문에 평균 손 오차가 작아 보일 수 있다. **추종 오차와 생존 시간·낙상을 함께** 판단해야 한다. 높은 상관관계만으로 좋은 제어라고 결론 내리지 않는다. 지연 상관에서 얻은 값은 해당 저주파 동작과 정책 반응의 관계이며, 네트워크·ALVR의 실제 전송 지연을 측정한 값이 아니다.

## 실행과 그림

```bash
python scripts/g1/analyze_results.py \
  runs/baseline_stand_v3 runs/evaluate_stand \
  --output runs/comparison_stand --plot
```

필요 라이브러리는 NumPy, 그림을 만들 때만 Matplotlib이다. 생성물:

- `analysis.json`: 집계, 유한성, 경계 제외 수, 환경 0 추적·응답 진단과 비교 조건 차이.
- `*_trace.png`: 목표/실제 3차원 점과 점별 오차. 제외된 리셋 구간은 선으로 연결하지 않는다.
- `comparison.png`: 전체 환경의 평균 손 오차, 시간당 낙상, 완료 에피소드 시간 비교.

자동으로 motion SHA256, seed, 환경 수, 평가 분할, 좌표 버전, 환경 소스 해시, 제어 주기와 액션 계약 차이를 표시한다. 지표가 같은 조건에서 얻어졌는지 확인한 뒤 그림을 해석한다. 일반적인 성공 임계값을 임의로 정하지 않는다.

```bash
python -m unittest discover -s tests/g1 -p 'test_analysis.py' -v
```

테스트는 리셋 순간의 큰 위치·관절 점프가 실제 추종 오차나 속도로 계산되지 않는지, 비유한 값이 숨겨지지 않는지, 알려진 응답 이득을 복원하는지, 유효한 행이 없을 때 결과가 명시적으로 비어 있는지 확인한다.

## 이번 실행의 기구학 확인

`runs/baseline_stand_v3/run_config.json`에 기록된 독립 기구학 비교에서 4개 환경의 머리·양손 지점과 NumPy FK의 최대 차이는 **1.565×10⁻⁶ m**, 평균 **8.270×10⁻⁷ m**였다. 허용오차 0.002m 이내다. 이는 USD 관절 프레임·순서·머리 로컬 offset 계약이 일치한다는 뜻이며 정책의 균형 유지 성능을 뜻하지 않는다.

중립 PD 기준선의 제자리 평가 결과: 64환경 ×1500스텝, 전체 1920시뮬레이션 초에서 1181낙상, 0시간 종료, 완료 에피소드 평균1.5766초. 전체 환경 평균 손 오차0.08749m, 머리 오차0.11058m였다. 이 환경에서는 중립 PD만으로 안정적인 자세를 유지하지 못하므로 학습 정책의 균형 개선을 따로 확인해야 한다.

혼합 동작 기준선도 완료했다. seed2026, 64환경 ×3000스텝, 전체3840시뮬레이션 초에서 2827낙상, 0시간 종료, 완료 에피소드 평균1.34234초였다. 전체 환경 평균 손 오차0.26618m, 머리 오차0.14731m였다. 혼합 동작은 더 넓은 팔·몸통 움직임을 포함하므로 위 제자리 기준선과 직접적인 향상률을 계산하면 안 된다. 해당 기구학 비교 최대 오차는2.721×10⁻⁶m였다.

두 기준선의 환경0 trace에서 목표점·실제 점·관절·액션은 모두 유한했다. 제자리 trace는1500행 중1443행, 혼합 trace는3000행 중2868행을 경계 제외 후 사용했다. 제외 전 환경0 리셋 수는 각각19회,44회이며 전체 환경 낙상 수와 다르다. 전체 분석과 PNG는 `runs/baseline_analysis/`에 생성했다.

## 제자리 500업데이트 정책의 별도 평가

`runs/stand_2048_v2/model_final.pt`와 내용이 같은 `policy.pt`를 TorchScript로 실행하여 기준선과 동일한 제자리 평가를 했다. 데이터 해시, seed42, 64환경,1500스텝, 환경 소스 해시와 액션 계약이 모두 같았다.

| 항목 | 중립 PD 기준선 | 학습된 제자리 정책 |
|---|---:|---:|
| 낙상 | 1181 | 0 |
| 20초 제한 도달 에피소드 | 0 | 64 |
| 완료 에피소드 평균 | 1.5766초 | 19.98초 |
| 평균 손 오차 | 8.749cm | 1.373cm |
| 평균 머리 오차 | 11.058cm | 1.113cm |

각 환경은20초 에피소드 1개를 완료한 뒤 추가10.02초를 진행했다. 따라서 연속30초 무리셋 시험이라고 부르지 않는다. 평균 손 오차는 기준선보다 약84.3% 감소했고, 환경0에서 왼손목 x축 목표 범위16.27cm에 실제 움직임 범위16.42cm로 반응했다. 해당 축 상관계수0.9928, 회귀 이득0.9826으로, 단순히 가만히 서 있는 상태와 구별된다. 이 응답 수치는 환경0 사례다.

trace의 목표·실제 점·관절·액션이 모두 유한했고, 자동 리셋 경계를 제외한1497/1500행을 분석했다. 결과와 그림은 `runs/comparison_stand500/`에 있다. 이 결과는 합성 제자리 평가 클립에 대한 것으로, 펀치·더 넓은 전신 동작이나 실제 Quest 입력에 그대로 일반화하지 않는다.

동일한 제자리500업데이트 모델을 **학습하지 않은 혼합 데이터 평가 클립**에도 적용했다. 혼합 기준선과 같은 seed2026·64환경·3000스텝에서2낙상,190시간 종료, 완료 에피소드 평균19.794초였다. 손 오차는13.001cm, 머리 오차4.904cm로, 혼합 기준선의 손26.618cm보다 작지만 제자리 평가보다 훨씬 크다. 즉 균형은 일부 일반화되었으나 넓은 동작 추종은 추가 학습이 필요하다. 해당 비교는 `runs/comparison_mixed_stand500/`에 있으며 비교 조건 차이는 없었다. 환경0 trace의 목표·실제 점·관절·액션은 모두 유한했고2991/3000행을 사용했다.
