# 초기 전신 추종 정책 분석과 다음 평가 기준

이 문서는 2026-09-30에 저장된 `sparse_positions_v1` 평가와
`sparse_tracking_v2` 400회 학습 후의 첫 평가를 분석한다.
아래 수치는 실제 시뮬레이션 평가 결과이며 Quest 장비 연결 결과가 아니다.

## 확인한 성능

원본 파일은 `runs/<평가 이름>/result.json`, 첫 번째 환경의 상세 궤적은
동일 디렉터리의 `trace.npz`다. 모든 표식 오차는 미터 단위다.

| 평가 | 표식 평균 오차 | 머리 | 양손 | 낙상 / 완료 에피소드 | 완료 에피소드 평균 길이 |
|---|---:|---:|---:|---:|---:|
| `eval_stand_500` — 작은 기립 동작 | 0.0129 | 0.0111 | 0.0137 | 0 / 64 | 19.98 s |
| `eval_mixed_stand500` — 기립 정책을 혼합 동작에 평가 | 0.1030 | 0.0490 | 0.1300 | 2 / 192 | 19.79 s |
| `eval_mixed_1200` — 혼합 학습 1200회 후 | 0.1356 | 0.0696 | 0.1685 | 23 / 192 | 18.99 s |
| `eval_rich_400` — 확장 관측으로 전환 후 400회 | 0.0774 | 0.0461 | 0.0931 | 2 / 192 | 19.84 s |

세 혼합 평가는 같은 평가 데이터와 seed 2026을 사용했다. 총 64개 환경에서
3000 스텝씩 실행했으며, 종료 직전 상태로 오차를 집계했다. 에피소드 종료
시점과 낙상이 달라지므로 후반의 실제 클립 배정은 정책별로 달라질 수 있다.
`0/64`도 충분히 긴 실제 운용에서 낙상이 없다는 보장은 아니다.

기립 정책은 작은 손 움직임에는 반응하지만, 큰 동작으로 범위를 넓혔을 때
추가 학습만으로 개선되지 않았다. 혼합 1200회 정책의 전 환경 평균 root
높이는 0.756 m로 기립 정책의 0.775 m보다 낮지만, 펀치 데이터의 기준
높이 0.717 m까지 충분히 내려가지 않는다. 이 데이터의 이동 명령은 모두
0이므로 낮은 속도 오차를 보행 성공으로 해석할 수 없다.

## 지연보다 큰 자세 편향

두 혼합 평가의 첫 번째 환경은 처음 900프레임의 목표가 정확히 같다.
첫 2초를 제외한 프레임 `[100:950]`에서 다음을 비교했다. 이는 한 환경의
특정 펀치 클립 분석이며 전체 데이터 평균과 구분해야 한다.

| 첫 환경 구간 통계 | 기립 500회 정책 | 혼합 1200회 정책 |
|---|---:|---:|
| 왼손 Z 평균 편향: 실제−목표 | -0.248 m | -0.237 m |
| 오른손 Z 평균 편향 | -0.256 m | -0.251 m |
| 머리 Z 평균 편향 | +0.059 m | +0.030 m |
| 왼손 X 진폭 비율: 실제 std / 목표 std | 0.420 | 0.258 |
| 오른손 X 진폭 비율 | 0.591 | 0.485 |
| X 상관이 최대인 양의 추종 지연 | 약 0.08–0.10 s | 약 0.08 s |

혼합 정책은 머리 높이를 일부 맞추지만 손은 목표보다 약 24–25 cm 아래에
남는다. 목표 변화와의 상관은 있어도 움직임 폭이 작다. 지연을 줄이는
것만으로 이 편향은 해결되지 않는다. 해당 전체 궤적의 액션 절댓값 최대는
2.36으로 제한값 4보다 작아, 액션 클리핑이 주원인이라는 근거는 없다.

혼합 정책 프레임 500과 표식이 가장 가까운 원본 데이터 프레임의 비교도
이를 뒷받침한다. 목표 표식 간 차이는 약 2.6 mm이며 완전히 같은 보간
프레임이라는 뜻은 아니다.

| 관절 | 가까운 기준 자세 | 실제 자세 |
|---|---:|---:|
| 왼쪽 무릎 | 0.913 rad | 0.621 rad |
| 오른쪽 무릎 | 0.913 rad | 0.643 rad |
| 왼쪽 팔꿈치 | -0.323 rad | +0.547 rad |
| 오른쪽 팔꿈치 | -0.412 rad | +0.440 rad |

초기 기준 자세에서 시작해도 정책은 팔을 낮게 접은 자세로 돌아가는 경향이
있다. 절대 목표 위치만 제공했던 v1에는 실제 손 위치와의 오차 및 목표
속도가 없었다. v2가 추가하는 실제 root 속도, 표식 오차, 목표 속도는
이 정보 부족을 줄이는 변경이다.

확장 관측 v2의 첫 평가 `eval_rich_400`에서는 양손 평균 오차가 9.31 cm로
줄었고 낙상은 2/192회였다. 동일한 첫 환경 `[100:950]` 구간에서 왼손 Z
편향은 -12.2 cm, 오른손은 -5.1 cm로 줄었지만 머리 Z 편향은 +4.6 cm가
남았다. 이 구간도 기존 기립 정책과 목표가 정확히 같다. 관측 변경과 탐색
표준편차 감소, 추가 학습이 함께 적용되었으므로 관측 한 가지의 인과 효과를
분리한 실험은 아니다. 600회 부근 학습 로그가 더 좋아져도 별도 평가를
하기 전에는 최종 성능으로 사용하지 않는다.

다음 CPU 명령으로 첫 환경의 편향과 진폭 비율을 다시 계산할 수 있다.

```bash
python - <<'PY'
import numpy as np
for name in ('eval_mixed_stand500', 'eval_mixed_1200'):
    with np.load(f'runs/{name}/trace.npz') as data:
        target = data['target'][100:950]
        actual = data['actual'][100:950]
    print(name)
    print('mean actual-target [head,left,right] xyz:', (actual-target).mean(0))
    print('std(actual)/std(target):', actual.std(0) / np.maximum(target.std(0), 1e-8))
PY
```

궤적은 관측 갱신 후 기록되어 1스텝 목표 시간차가 포함될 수 있다. 리셋
프레임의 실제 자세도 초기 자세이므로 그 프레임과 직후 과도 구간을 제외해야
한다. 전체 성능 판정은 `result.json`의 리셋 전 집계를 우선한다.

## 보상에서 의심되는 원인과 제한된 후속 실험

현재 표식 보상은 `4 * mean(exp(-point_error² / 0.04))`다. 오차가 0.30,
0.40, 0.50 m일 때 지수항은 각각 약 0.105, 0.018, 0.0019까지 감소한다.
손이 멀어지면 복구 방향에 대한 보상 차이가 작아지고, 머리 하나를 잘 맞춰도
표식 보상의 최대 1/3을 얻는다. 살아 있기, 정지 속도, yaw 속도, 높이,
수직 자세 항은 합계 최대 6/초여서 손을 잘 못 맞춰도 균형 자세가 높은
보상을 얻을 수 있다. 관절 오차를 29개 전체에서 평균내므로 큰 팔꿈치 오차가
다른 관절에 의해 희석될 가능성도 있다. 이는 코드와 궤적에 근거한 가설이다.

우선 현재 진행하는 v2의 1000회 이후 체크포인트도 같은 조건으로 평가한다. 여전히 큰 편향이
남으면 아래 중 하나씩만 바꾸고 동일한 전체 범위 평가로 비교한다.

1. 기립 자세에서 목표 관절 자세까지 25%, 50%, 100%로 동작 폭을 늘리는
   교육과정을 사용한다. 관절 보간 뒤 FK와 root 높이를 다시 계산하여 표식과
   자세 기준이 일치하게 한다. 평가 목표는 계속 100%로 유지한다.
2. 손 위치 오차에 작은 거리 또는 Huber 페널티를 추가해 큰 오차에서도
   개선 방향이 보상에 남게 한다. 예를 들어 양손 평균 거리에 `-2/초/m`
   정도부터 별도 실험하되 낙상률과 액션 변화량을 함께 확인한다.
3. 팔/다리 관절 기준 항을 그룹별로 평가한다. 손 위치만으로 손목 회전 전체를
   관측할 수 없으므로 모든 관절 기준을 무조건 강화하지 않는다.

현재 증거로 PD나 토크 상한을 먼저 바꿀 이유는 없다. 관측·보상 변경과
물리 변경을 동시에 하면 어느 변경이 효과를 냈는지 구분하기 어렵다.

일부 동작이 따라오기 시작한 뒤에는 정밀도용 짧은 추가 학습도 별도 후보가
된다. 현재 높이 보상 `exp(-height_error²/0.01)`은 높이 오차 5 cm에서도
약 0.779/초를 주므로 정확한 높이의 1/초와 차이가 작다. 표식 보상 분모도
0.04라 폭이 넓다. 별도 정밀도 단계의 후보는 표식 보상을
`6*mean(exp(-point_error²/0.01))`, 높이 항을
`2*exp(-height_error²/0.0025)`로 바꾸고 낙상 비용을 2에서 5로 높이는 것이다. 높이
5 cm 오차에서 이 후보 보상은 약 0.736/초, 정확할 때는 2/초가 된다.

먼저 현재 안정적인 체크포인트를 보존하고 정밀도 단계 200–500회만 실행해
원래 평가와 비교한다. 좁은 표식 보상은 큰 오차에서 다시 포화되므로 처음부터
적용하거나 범위가 큰 동작의 학습을 대체하지 않는다. 평균뿐 아니라 손 오차
p95, 머리 Z 편향, 클립별 낙상률과 완주 시간을 확인한다. 높이만 맞추려고
과도하게 웅크리거나 균형이 나빠지면 이 변경을 채택하지 않는다.

이 실험을 위한 설정 필드는 기본 환경에 구현했으며 기본값은 기존과 동일하다.
`tracking_reward_weight=4`, `tracking_error_variance=0.04`,
`height_reward_weight=1`, `height_error_variance=0.01`, `fall_cost=2`다.
메타데이터 `reward_contract`에 다섯 값을 기록한다. 낙상 비용은 한 사건당
즉시 차감하고, 다른 보상은 제어 주기를 곱한다. 수정 전 파일은
`backups/20260930_precision_reward_config/env.py`에 보관했다. CPU 테스트
6개 및 수정 전후 무작위 상태 64개의 기본 보상·누적값·지표 일치 검증을
통과했지만, 이것은 정밀도 설정의 학습 성능 검증이 아니다.

## 조이스틱 이동 정책의 별도 평가안

`velocity_env.py`는 이동 명령을 샘플링하지만, 코드가 있다는 사실은 이동
성능의 증거가 아니다. 아래는 이 프로젝트에서 사용할 수 있는 제안 기준이며
H2O의 공식 벤치마크나 이미 달성한 성능을 뜻하지 않는다.

- 5초 블록으로 정지, vx=±0.15/±0.30 m/s, vy=±0.075/±0.15 m/s,
  yaw=±0.20/±0.40 rad/s를 각각 평가한다. 복합 명령도 포함하고 순서를
  바꾼 seed를 최소 3개 사용한다. 학습용 무작위 명령열을 그대로 재사용하지 않는다.
- 첫 1초의 응답 과정을 따로 보고, 다음 4초의 축별 MAE, XY norm 오차,
  yaw MAE, p95 오차와 실제/명령 속도 비율을 기록한다. 정지 구간과 이동
  구간을 분리하고, 축별 평균 속도의 부호 상쇄로 성능을 판단하지 않는다.
- 예비 통과 기준은 vx MAE≤0.05 m/s, vy≤0.04 m/s, yaw≤0.08 rad/s,
  정지 XY drift≤0.03 m/s, 정지 yaw≤0.05 rad/s다. 각 명령별 정상 구간의
  속도 비율이 대략 0.7–1.3인지도 확인하여 가만히 있는 정책이 통과하지 않게 한다.
- 20초 에피소드 최소 300개에서 낙상률·완주율을 보고한다. 예비 낙상률
  기준은 1% 이하로 두되 신뢰구간을 함께 제공한다. 300회에서 0회 낙상도
  독립 표본 가정에서 95% 상한이 대략 1%다. 전환 직후 낙상도 제외하지 않는다.
- 이동 중 머리·손 추종 오차와 정지 복귀 시간을 함께 측정한다. 속도 추종만
  좋아지고 상체 추종이나 안정성이 크게 나빠지면 전신 텔레옵 통과로 보고하지 않는다.

`moving_velocity_replacement_v2`는 이동 구간의 속도 보상을 선명하게 만든
별도 변경이다. 구현 수식과 설정은 [LOCOMOTION.md](LOCOMOTION.md)를 참고한다.
이 변경의 CPU 단위 테스트는 수식 대체·로그 일치만 검증하며 보행 학습을
검증하지 않는다.

## Root 이동과 발 접촉의 추가 진단

`scripts/g1/analyze_results.py`는 trace에 `root_position_w`,
`root_quaternion_wxyz`, `root_linear_velocity_b`, `foot_contact`,
`foot_linear_velocity_w`가 있으면 `trace.locomotion` 보고서를 추가한다.
이 필드가 없는 기존 trace의 결과는 그대로 유지한다. 일부 필드만 있는
경우에는 가능한 지표만 계산하고 누락 필드를 명시한다.

- 리셋·유효하지 않은 상태로 끊긴 각 구간에 대해 root의 평면 순변위,
  이동 경로 길이, yaw 누적 변화, 로봇 속도를 계산한다. 서로 다른 에피소드
  사이의 순간이동은 이동 거리나 yaw drift에 더하지 않는다.
- 왼발·오른발 접촉 비율과 이륙·착지 횟수를 계산한다. 리셋 경계를 가로지르는
  접촉 변화는 실제 이륙·착지로 세지 않는다.
- 접촉 중인 발 **링크 원점**의 월드 XY 속도 평균·중앙값·p95·최댓값을
  기록한다. 발이 접촉점을 중심으로 회전해도 링크 원점은 움직일 수 있으므로
  이 값은 정확한 접촉점 미끄러짐 속도가 아니다.

진단 필드의 NaN/Inf, 단위 길이가 아닌 quaternion, 0/1이 아닌 접촉 값은
`invalid_rows`에 기록하고 `data_valid=false`로 표시한다. 해당 행은 구간을
나누며 수치 집계에서 제외한다. 유효 표본이 없으면 평균을 0으로 보고하지
않는다. 이 진단은 환경 0의 리셋 이후 trace에 관한 것이며, 전체 환경의
리셋 전 낙상 통계는 기존 보고서를 사용한다. 명령 속도를 따라가는 것만으로
검증된 보행이라고 판정하지 않고, 정지 시 drift·발 접촉·낙상 결과를 함께 본다.

수정 전 분석기·테스트·문서는 `backups/20260930_root_foot_analysis/`에
보관했다. 리셋 점프를 제외한 알려진 이동 거리·yaw 변화와 발 접촉 전환,
잘못된 데이터 처리를 포함한 CPU 분석 테스트 12개를 통과했다.
